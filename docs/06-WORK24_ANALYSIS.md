# 06. Work24 Analysis

## 1. 수집 대상

현재 1차 수집 대상은 Work24 채용정보 목록 화면이다.

기준 URL:

`https://www.work24.go.kr/wk/a/b/1200/retriveDtlEmpSrchList.do`

사용자가 확인한 목록은 `resultCnt=50`으로 페이지당 50건을 표시하며 페이지 파라미터를 이용해 다음 페이지를 요청할 수 있다.

## 2. 수집 전략

1. 목록 페이지 요청
2. 목록 HTML 구조 분석
3. 공고 식별자 추출
4. 공고 제목/회사/근무지/급여/마감일/상세 URL 등 추출
5. 필요한 경우 상세 페이지 요청
6. 데이터 정규화
7. MariaDB UPSERT

## 3. 페이지네이션

페이지 이동 파라미터와 실제 응답 결과의 관계를 반드시 HTML/네트워크 확인으로 검증한다. URL에 보이는 `currentPageNo`, `pageIndex` 등의 값이 실제 서버 동작에서 어떤 역할을 하는지 코드로 고정하기 전에 테스트한다.

## 4. HTML 파싱

CSS selector는 사이트 구조 변경에 취약하므로 한 곳에 모아 관리한다. 파싱 실패 시 전체 수집을 중단하기보다 해당 공고를 오류로 기록하고 다음 공고를 처리할 수 있도록 한다.

## 5. 주의사항

- Work24의 이용약관, robots 정책, 접근 제한을 확인한다.
- 요청 빈도를 과도하게 높이지 않는다.
- 서버 오류 시 exponential backoff를 고려한다.
- 수집하지 않아도 되는 개인정보는 저장하지 않는다.
- 원본 HTML 장기 저장은 필요성과 보관정책을 검토한 후 결정한다.

## 6. 개발 검증 항목

- 첫 페이지 50건 수집
- 두 번째 페이지 50건 수집
- 마지막 페이지 처리
- 동일 공고 재수집 시 중복 제거
- 상세 URL 정상 접근
- 일부 HTML 누락 시 graceful degradation
- 페이지 구조 변경 시 파싱 실패 감지
